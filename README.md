# Queueless-Clinic-Management-System

**Course:** IT211  
**Section:** BSIT 2-3  
**Group:** 2

## Project Description

The QueueLess Clinic System is a software project designed to improve clinic operations by reducing long waiting lines through scheduled appointments, digital patient registration, and organized queue management. It aims to minimize patient waiting time, prevent overcrowding, and provide a more convenient and efficient clinic experience.

## Repository Structure

- `diagrams/` – Contains UML diagrams and other system diagrams.
- `docs/` – Contains project proposals, requirements, and documentation.
- `src/` – Contains the project's source code.

## Branching Convention

| Branch | Purpose |
|---|---|
| `main` | Stable and approved project code. |
| `develop` | Integration branch for ongoing development. |
| `feature/feature-name` | Branch for developing specific features. |
| `fix/issue-name` | Branch for fixing bugs and issues. |
| `docs/topic-name` | Branch for documentation updates. |

All feature branches should be reviewed before merging into `develop`.

## Commit Message Convention

Use the following format:

`type: short description`

**Examples:**

- `feat: add patient registration`
- `fix: resolve appointment scheduling issue`
- `docs: update project requirements`
- `style: improve clinic dashboard layout`
- `test: add patient registration test cases`
- `chore: organize repository folders`

## Team Collaboration Rules

1. Every member must use their own GitHub account.
2. Members should work on their assigned branches.
3. Changes must be committed using descriptive commit messages.
4. Pull requests should be reviewed before merging.
5. Do not commit passwords, API keys, or confidential information.
6. All members must keep the shared repository updated.
7. The Project Manager monitors repository progress and task completion.
